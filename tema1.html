1 · Ecosistema de datos

El mapa del ecosistema de datos

Primero vamos a comprender la diferencia entre los sistemas que registran la operación y los sistemas que analizan la información. Después veremos dónde se almacenan esos datos y cómo podemos moverlos con Python.

1.1 · OLTP vs OLAP

OLTP: el sistema que hace funcionar la operación

OLTP significa On-Line Transaction Processing. Son los sistemas que registran la operación diaria del negocio.

En un sistema OLTP encontramos muchas transacciones pequeñas, simultáneas y rápidas: crear un usuario, registrar una venta, actualizar un inventario o realizar una matrícula.

Lo importante aquí es que la operación quede correctamente registrada en el momento en que ocurre.

Ejemplos: una app de domicilios registrando un pedido, un cajero procesando un retiro o el sistema de la universidad registrando una matrícula.
1.1 · OLTP vs OLAP

OLAP: el sistema que ayuda a entender el negocio

OLAP significa On-Line Analytical Processing. Su finalidad es analizar datos históricos para apoyar decisiones.

Las consultas pueden involucrar miles o millones de registros y operaciones como sumas, promedios, comparaciones y agrupaciones.

Un ejemplo sería analizar cuál fue la ciudad con más ventas durante el último trimestre.

1.2 · Data Warehouse

Data Warehouse: datos preparados para analizar

Un Data Warehouse es un repositorio central de datos que han sido limpiados, integrados y estructurados específicamente para responder preguntas analíticas.

Orientado a un temaIntegrado No volátilVariable en el tiempo

Orientado a un tema: organiza la información alrededor de temas del negocio como ventas, clientes o estudiantes.

Integrado: combina datos procedentes de diferentes sistemas y los lleva a formatos consistentes.

No volátil: conserva la información histórica.

Variable en el tiempo: permite comparar periodos diferentes.

El proceso que lleva los datos desde sus fuentes hasta el Warehouse se conoce como ETL: Extract, Transform y Load.

1.2 · Data Warehouse

ETL: preparar antes de analizar

Extract

Extraer datos desde los sistemas donde se generan.

Transform

Limpiar, unificar formatos, corregir valores y calcular nuevas columnas.

Load

Cargar la información preparada en el repositorio analítico.

Analogía: el Warehouse se parece a un archivador de oficina muy ordenado. Antes de guardar un documento, se clasifica, se etiqueta y se coloca en la carpeta correcta.

Por eso un Warehouse puede integrar, por ejemplo, matrícula, notas y bienestar universitario para analizar fenómenos como la deserción por facultad y semestre.

1.3 · Data Lake

Data Lake: guardar el dato tal como llega

Un Data Lake es un repositorio centralizado que conserva los datos en su formato original o crudo.

Puede almacenar datos estructurados, semi-estructurados y no estructurados.

La diferencia clave está en cuándo se define la estructura.

Schema-on-read: los datos se guardan primero y se decide cómo interpretarlos cuando van a utilizarse.

Importante: su flexibilidad permite almacenar gran variedad de información, pero sin una buena organización y gobernanza puede convertirse en un “pantano de datos” o data swamp.

1.4 · Lakehouse

Lakehouse: la combinación de dos mundos

El Lakehouse busca conservar la flexibilidad y el bajo costo del Data Lake, pero incorporar garantías de calidad, consistencia y estructura propias de un Warehouse.

La arquitectura incorpora una capa de metadatos y control transaccional sobre los archivos del Data Lake.

1.4 · Delta Lake · Iceberg · Hudi

Tres tecnologías asociadas al Lakehouse

Delta Lake

Impulsado por Databricks. Utiliza un registro de transacciones conocido como Delta Log y presenta una fuerte integración con Apache Spark.

Apache Iceberg

Impulsado originalmente por Netflix. Es un formato de tabla abierto y maneja bien los cambios de esquema a lo largo del tiempo.

Apache Hudi

Impulsado originalmente por Uber. Está orientado a actualizaciones incrementales rápidas, incluidos procesos de upsert y escenarios de streaming.

La idea fundamental es entender qué problema resuelven: aportar capacidades de consistencia y transacciones sobre el entorno flexible de un Data Lake.
1.5 · Modelos de datos

Modelar los datos: normalización

Normalizar significa organizar las tablas de una base de datos para reducir la redundancia y evitar inconsistencias.

En un entorno OLTP

Cada dato procura vivir en un solo lugar. Esto hace que las actualizaciones sean seguras y reduce la duplicación.

La consecuencia es que las consultas analíticas pueden necesitar muchos JOIN.

Ejemplo conceptual

En vez de repetir la información completa de un cliente en muchas filas, se mantiene una tabla de clientes y las demás tablas se relacionan mediante claves.

Objetivo de la normalización: mantener la integridad y disminuir la redundancia.
1.5 · Modelo estrella

Modelo estrella: organizar para consultar rápido

El modelo estrella organiza una tabla de hechos en el centro y varias tablas de dimensiones alrededor.

La tabla de hechos contiene las medidas numéricas del negocio y las claves que conectan las dimensiones.

Las dimensiones contienen los atributos descriptivos que permiten filtrar y agrupar.

2.2 · Extracción de datos desde APIs

Trabajar con una API

Una API es una forma de comunicación entre sistemas. En lugar de entrar directamente a la base de datos del servidor, hacemos una solicitud y recibimos una respuesta.

Una respuesta frecuente es JSON, un formato estructurado formado por pares de clave y valor.

Analogía: una API funciona como un mesero. Nosotros hacemos el pedido y el mesero lleva la información solicitada sin necesidad de entrar a la cocina.
import requests
import pandas as pd

url = "https://jsonplaceholder.typicode.com/users"

respuesta = requests.get(url)
print(respuesta.status_code)

datos = respuesta.json()

df_usuarios = pd.DataFrame(datos)
print(df_usuarios[["name", "email"]].head())

Los códigos más comunes que veremos durante la depuración son 200 para una respuesta correcta, 404 cuando el recurso no se encuentra y 500 cuando existe un error del servidor.

2.2 · APIs

Cuando el JSON viene anidado

La respuesta de una API no siempre llega como una tabla plana. Es posible que algunos datos estén dentro de otros objetos.

# Primero observamos la estructura

2.3 · Web scraping

Web scraping: extraer información del HTML

El web scraping consiste en extraer información directamente del HTML de una página web.

Se utiliza especialmente cuando la información que necesitamos no está disponible mediante una API.

Es una técnica más frágil porque un cambio en la estructura de la página puede hacer que el código deje de funcionar.

Buenas prácticas: revisar las reglas del sitio, leer sus condiciones de uso y evitar hacer peticiones demasiado frecuentes.
2.3 · Web scraping

Código de scraping con BeautifulSoup

import requests
from bs4 import BeautifulSoup

url = "https://quotes.toscrape.com/"

respuesta = requests.get(url)
soup = BeautifulSoup(respuesta.text, "html.parser")

citas = soup.find_all("span", class_="text")
autores = soup.find_all("small", class_="author")

for cita, autor in zip(citas, autores):
    print(f"{cita.text} — {autor.text}")

La parte más importante no es memorizar find_all(). Lo esencial es aprender a inspeccionar el HTML de la página y localizar las etiquetas y clases que contienen la información que necesitamos.
